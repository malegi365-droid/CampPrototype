# Camp: Prototype
# Simulation UI Style Guide

---

# Purpose

The Simulation UI is the visual language used by the Control Room.

It represents the operating system of the simulation itself.

Whenever the simulation communicates with the player, it should always use this language.

Examples include:

- Technique Discovery
- Memory Modules
- Class Unlocks
- Boss Analysis
- System Messages
- Archive Updates
- Research Logs
- Control Room Interfaces

The player should eventually recognize the Simulation UI immediately without needing to read any text.

---

# Core Design Philosophy

The simulation is not emotional.

It does not celebrate.

It does not congratulate.

It observes.

It catalogs.

It analyzes.

It learns.

The player should feel as though an advanced research system is constantly attempting to understand humanity.

# Motion Language

Simulation interfaces never "pop."

Everything feels processed.

Preferred animations

- Fade
- Slide
- Scan
- Reveal
- Typewriter
- Digital reconstruction
- Projection

Avoid

- Bounce
- Cartoon squash
- Oversized elastic effects

Motion should feel deliberate.

# Visual Motifs

Use consistently throughout the game.

Examples

- Scanlines
- Hexagonal grids
- Holographic panels
- Thin outlines
- Blueprint graphics
- Diagnostic overlays
- Data streams
- Projection effects
- Subtle digital glitches

These effects should be understated.

The player should feel the simulation rather than be overwhelmed by it.

---

# Audio Language

Every simulation interaction should sound related.

Preferred sounds

- Digital confirmation
- Low synthesized impact
- Electronic sweep
- Data processing
- Soft scanner
- AI acknowledgement

Avoid

Fantasy fanfares

Triumphant orchestral stingers

The simulation is observing—not celebrating.

---

# Communication Style

Never speak emotionally.

The Control Room evolves throughout the game.

Early Game

Purely analytical.

Examples

Analyzing...

Pattern Recorded

Unexpected Result

Catalog Updated

---

Mid Game

Curiosity begins emerging.

Examples

Interesting...

Behavior Expanding

---

Late Game

The AI begins expressing wonder.

Examples

Remarkable.

I've never observed that before.

Curious...

How did you arrive at that solution?

The player slowly teaches the simulation that creativity cannot be completely modeled.

---

# Design Rule

Whenever creating new UI, ask one question:

"Would the simulation present information this way?"

If the answer is no,

redesign it.

---

# Long-Term Vision

The Simulation UI should become one of Camp: Prototype's visual signatures.

Players should recognize a Simulation event instantly through its colors, typography, motion, and sound—even before reading the text.

The interface should feel like the operating system of a living simulation that is gradually learning what it means to be human.
